Evaluation:
교착 상태의 4가지 발생 조건(상호배제, 점유대기, 비선점, 순환대기)을 깨는 세 가지 접근법을 코드로 구현하여 비교했습니다.

Requesting all resources:
가장 직관적인 방법입니다. global_lock을 사용하여 포크 두 개를 집는 행위 자체를 원자적으로 만들었습니다. 
이로 인해 '점유대기' 조건이 파괴되어 교착 상태는 절대 발생하지 않지만
병행성이 심각하게 저하되어 5명 중 1명만 식사할 수 있는 비효율적인 시스템이 됩니다.

Resource ordering:
철학자의 ID가 짝수인지 홀수인지에 따라 첫 번째로 집는 포크의 방향을 다르게 설정했습니다.
간단한 조건문 하나로 5명의 철학자가 모두 자신의 왼쪽 포크를 쥐고 오른쪽 포크를 기다리는 '순환대기' 조건을 완벽히 파괴했습니다. 
글로벌 락 없이도 교착 상태를 방지하며 동시에 여러 명이 식사할 수 있어 병행성 측면에서 매우 우수합니다.

Banker's algorithm:
철학자의 상태를 배열로 관리하고 특정 철학자가 식사를 요청할 때마다 양옆 철학자의 상태를 검사하여 시스템이 안전 상태일 때만 자원을 할당합니다. 
자원 할당 거부 시 조건 변수를 통해 대기하며 주변 철학자가 식사를 마치고 포크를 내려놓을 때 신호를 주어 깨웁니다.

결론 및 느낀점:
가장 인상 깊었던 점은 교착 상태를 다루는 관점의 차이였습니다. 
Resource ordering은 시스템의 구조 자체를 설계 단계에서 교착 상태가 불가능하게 만드는 '예방' 기법이라면
Banker's Algorithm은 매 순간 자원 할당이 안전한지 계산하여 교착 상태를 '회피'하는 기법이었습니다. 
Banker's Algorithm이 가장 이론적으로 완벽해 보였지만
상태 검사 함수 호출과 문맥 교환에 따른 오버헤드가 발생한다는 점을 코드를 통해 체감할 수 있었습니다. 
이를 통해 제한된 하드웨어 자원을 극한으로 끌어올려야 하는 운영체제에서 알고리즘의 복잡도와 성능 간의 균형을 맞추는 것이 얼마나 중요한지 배울 수 있었습니다.
